# Отчёт о стандартах — Memorial Modern 5.1.0 и Memorial Plugin 2.1.0

Все проверки ниже запускаются в CI (`.github/workflows/ci.yml`) на каждый push в `block-migration` / `stage-*` и на pull request. Финальная версия 5.1.0 / 2.1.0 проходит их без ошибок.

С 12.11.2026 полный WPCS включён для всего кода: перенесённые модули 1.15.0 (каталог, цены, отзывы, Rewio, SEO) переформатированы, вывод экранирован. Функции, которые возвращают уже экранированную разметку (`memorial_plugin_icon()`, `memorial_plugin_laurel()`, `memorial_plugin_e()` и т. п.), перечислены в `customAutoEscapedFunctions`; оставшиеся `phpcs:ignore` — с причиной в той же строке (код счётчиков и виджетов, который сохраняет только администратор с правом `unfiltered_html`, вывод `the_content`). Переменные в шаблонах `blocks/legacy/render/` — локальные переменные функции `memorial_plugin_legacy_render()`, поэтому правило префиксов глобальных переменных для этой папки отключено.

## Допущения, отклонения от ТЗ, открытые вопросы

**Допущения.**
- Язык сайта — русский (`ru_RU`); русский перевод в комплекте с плагином и темой.
- Содержимое по умолчанию осталось русским и не переводится: тексты главной, услуг, пакетов, шаблоны документов по 152-ФЗ, ключевые слова поиска. Это данные русскоязычного сайта, а не интерфейс.
- Удаление плагина по умолчанию не трогает содержимое (ТЗ, раздел 7: «не удалять пользовательские данные без явной миграции и резервного механизма»). Полное удаление — по константе `MEMORIAL_PLUGIN_DELETE_DATA`.

**Отклонения (согласованы с заказчиком).**
- **Слой совместимости.** Шорткоды `[mem_…]` — задокументированный слой (`core/shortcodes-compat.php`): шорткод в тексте работает до 3.0.0 и при каждом использовании сообщает `_deprecated_function()` (видно при `WP_DEBUG`) с названием блока-замены. Перевод записи — командой редактора «Перевести шорткоды в блоки» с откатом (экран «Перевод в блоки» удалён по решению 13.11).
- **Таблица товаров — только таблица**, без режимов «сетка» и «список» DataViews (решение 13.11, ТЗ п. 3.2.1).
- **Блоки шаблонов (`blocks/legacy`)** — шапка, подвал, товар, раздел каталога, 404 и т. п. Их разметка — несколько корневых элементов в сетке темы, поэтому стилевых `supports` у них нет; у остальных блоков — цвет, типографика, отступы, рамка. `block.json` есть у всех 51 блока (`blocks/types/`, собирает `tools/block-json.php`).
- **Паттерны плагина** регистрируются из PHP (`content/patterns.php`), а не папкой `/patterns`: WordPress сам читает папку `patterns/` только у темы.
- **Стили админки.** Экран «Отзывы Rewio» — разметка сервера, стили и скрипт — отдельные файлы, подключаются только на этом экране, без jQuery. Общий вид экранов плагина (бумажный фон, карточки, акцент) — стили только для контейнеров плагина, по просьбе заказчика; ядро не переопределяется.
- **Яндекс Метрика** загружает `tag.js` с серверов Яндекса — это сам счётчик, локальной копии у него нет; загрузка — только после согласия посетителя (режим «ask»).
- **Почта о заявках** — через `wp_mail()` хостинга, без SMTP (решение 14.11).
- **Ключевые слова паттернов темы** (`Keywords`) переводятся с контекстом `Pattern keyword`. WordPress может не переводить их при выводе — тогда поиск по паттернам находит их по-английски.

**Открытые вопросы.**
- Ручная проверка скринридерами (NVDA, VoiceOver) — см. «Доступность».
- Конец поддержки шорткодов (3.0.0).
- `!important` в CSS: тема — 18, плагин — 33 (состояния, скрытые элементы, редактор).
- ESLint и Stylelint проверяют `src/` и модули `assets/js/view`; файлы `assets/css/*.css` и `assets/js/admin` Stylelint/ESLint не проходят.
