# Сайт «Мемориал»: руководство по доработке

Этот файл заменяет исходное ТЗ на миграцию. Миграция закончена. Здесь записано, как вносить правки дальше: где что лежит, как проверять и в каком стиле делать сайт и админку. Сюда же собраны решения заказчика, принятые по ходу работы. Подробности и даты — в файлах `claude/decisions-*.md` проекта.

## 2. Главные правила

1. **Сначала план, потом работа.** На каждую задачу — короткий план. Неясное спрашивать до начала. Отдельно отметить, что из ТЗ и решений ниже задача затрагивает.
2. **Не ломать то, что работает.** Перед правкой посмотреть, где ещё используется код. После правки проверить соседние экраны и страницы.
3. **Требования ниже обязательны**, кроме согласованных отступлений (раздел 10).
4. **По максимуму — в GitHub Actions**: сборка, проверки, проверка на копии сайта, диагностика живого сайта, уборка веток. Локально — только быстрые проверки.
5. **Выгрузка на сайт — только по команде владельца.** Выгружает он сам: Actions → «Деплой на сайт». Перед выгрузкой — резервная копия UpdraftPlus.
6. **Коммиты — на русском.** В конце коммита строки авторства, если работает ИИ.
7. **Данные сайта не удалять и не портить.** Любое изменение данных — однократный перенос с флагом и журналом (раздел 8.4). Проверять его сначала вхолостую.
8. **Сайт и админка должны выглядеть единообразно** (разделы 6 и 7). Новое делается по образцу уже существующего.

## 3. Как вносить правку (по шагам)

1. `git fetch`, ветка от свежей `block-migration`: `git checkout -b <короткое-имя>`.
2. Правка кода.
3. Если менялись строки интерфейса:
   - `php tools/i18n.php pot`;
   - дописать перевод в `memorial-*/languages/*-ru_RU.po`;
   - `php tools/i18n.php build`;
   - `php tools/i18n.php check` — должно быть 0 непереведённых строк.
4. Если менялся `assets/css/*.css` или `assets/js/**/*.js`, у которых есть `.min`-копия: `php tools/minify.php <исходник>`.
5. Если менялись атрибуты блоков: `php tools/block-json.php build`, затем `php tools/blocks-doc.php build`. Новый блок — новый раздел в `BLOCKS.md` (справочник по блокам; CI проверяет).
6. Быстро локально:
   - `php -l` для изменённых PHP;
   - `node --check` для JS;
   - `php tools/check-prefixes.php`.
7. `git push -u origin <ветка>`.
8. Автоправка оформления: `git push -f origin <ветка>:autofix/<ветка>`, подождать 1–2 мин, затем `git pull --ff-only origin <ветка>`.
   - Если автоправка изменила исходник JS, у которого есть `.min.js`, — пересобрать копию (шаг 4) и запушить снова.
9. Все проверки с WordPress: `gh workflow run ci.yml --ref <ветка> -f wordpress=true` (около 10 мин). Должно быть зелёным.
10. Проверка на копии живого сайта для видимых изменений:
    - сценарий в `tests/probe/probe.spec.js`;
    - в `tests/probe/run.env` — `PROBE_GREP='<сценарий>'`, `PROBE_PHASES='block'`, `PROBE_UPLOADS=1`;
    - `git push -f origin <ветка>:probe/<имя>`;
    - около 35 мин; результат и снимки — в ветке `ci-probe` (`block/…`).
    - Смотреть снимки **ПК (1440) и телефона (390 и 360)**, а не только цифры.
11. `CHANGELOG.md` — короткий раздел сверху.
12. Слияние:
    - `git checkout block-migration && git merge --no-ff <ветка>` с понятным сообщением;
    - `git push`;
    - снова CI для `block-migration`.
13. Уборка служебных веток: `git push origin block-migration:cleanup/runN`. Остаются только `main`, `block-migration`, `ci-probe`.
14. Записать решения и уроки в проект: `claude/decisions-<дата>-<тема>.md`.
15. Отчёт владельцу: что сделано, что проверено, что не сделано и почему.

## 4. Инструменты и GitHub Actions

| Что | Как запустить | Что делает |
|---|---|---|
| **Проверки** (`ci.yml`) | push в `block-migration` / `main`, или `gh workflow run ci.yml --ref <ветка> -f wordpress=true` | PHP (WPCS, совместимость, префиксы, PHPUnit), ESLint, Stylelint, JSON-схемы, контраст, сборка, свежесть `.min`, переводы, e2e в WordPress 7.1.4 |
| **Автоправка** (`autofix.yml`) | push `autofix/<ветка>` | Prettier / ESLint --fix, обновление package-lock; пушит в `<ветка>` |
| **Проверка на копии сайта** (`probe.yml`) | push `probe/<имя>` + `tests/probe/run.env` | копия базы и загрузок с хостинга (только чтение) → WordPress в Actions → сценарии Playwright → снимки и `log-*.json` в `ci-probe` |
| **Диагностика сайта** (`diag.yml`) | push `diag/<имя>` | кладёт на живой сайт временный PHP с ключом (`tests/diag/report.php`), получает отчёт **только для чтения** и сразу удаляет файл. Отчёт — `ci-probe:diag/report.json`. Так же выясняется ошибка 500 |
| **Деплой на сайт** (`deploy.yml`) | только владелец: Actions → Run workflow | сборка → все проверки → выгрузка SFTP в `.memorial-*-new` → подмена папок |
| **Скриншоты** (`screenshots.yml`) | push `shots/<имя>` | попиксельное сравнение страниц «до/после». Шумные страницы: главная (телефон), blagoustrojstvo, fotogalereia, groby, kontakty, otzyvy |
| **Уборка веток** (`cleanup-branches.yml`) | push `cleanup/<что-то>` | удаляет все ветки, кроме `main`, `block-migration`, `ci-probe` |
| **Иконки** (`icons.yml`) | push `icons/<имя>` | проверка перевода иконок в SVG Icon API |

Локальные инструменты в `tools/`:
- `i18n.php` — pot / build / check;
- `minify.php` — сжатые копии;
- `block-json.php` — build / check;
- `blocks-doc.php` — build / check справочника `BLOCKS.md`;
- `check-prefixes.php`;
- `check-templates.php`;
- `validate-json.mjs`, `check-contrast.mjs`;
- `css-check.mjs` — сравнение вычисленных стилей по «слепкам страниц» до и после правки CSS.

Готовые сценарии probe перечислены в `tests/probe/probe.spec.js`: аудит админки, блоков, подвала, цен, привязок, товаров; слепки страниц; пакеты; отзывы и разрешения; редактор сайта; тексты админки; описания и крошки; отзывы и почта; новая работа; просмотр; анимация. Новый видимый функционал — новый сценарий.

## 5. Структура

### Тема `memorial-theme/`
- `theme.json` v3 — единственный источник дизайна: палитра, шрифты, размеры, отступы, ширины (contentSize 1200px).
- `templates/`: front-page, page, page-kontakty, single, archive, search, 404, index.
- `parts/`: header, footer — из паттернов `patterns/header.php`, `footer.php`.
- `patterns/`: home, steps, note и др.
- `styles/`: вариации bronze, dark, stone.
- `assets/css/main.css` и `content.css` — встраиваются в страницу. Стили блоков ядра лежат в `assets/css/blocks/core-*.css` и подключаются через `wp_enqueue_block_style`.
- `inc/`: navigation (меню из «Навигации»), upgrade (разовые переносы темы), logo-sync, laurel.
- `functions.php` — подключение, предзагрузка шрифтов и фото первого экрана, встраивание стилей.

### Плагин `memorial-plugin/`
- Модули подключаются **списком `$memorial_plugin_modules`** в `memorial-plugin.php`. Новый файл без записи в этот список не загрузится.
- `core/` — настройки (схемы полей экранов), права, почта, ассеты, кэш страниц, разовые переносы (`upgrade.php`, `fix-uploads.php`).
- `catalog/` — товары `mem_product`, таксономия `mem_cat`: корневые термины — типы, дочерние — категории. Вывод разделов, типы и категории, страницы товаров, копии фото для карточек.
  - `catalog-io.php` — артикул `_mem_sku` и таблица товаров для выгрузки (.xlsx без библиотек, CSV);
  - `catalog-import.php` — импорт из таблицы с фото: проверка без записи, загрузка фото по одному, применение порциями, журнал и откат.
- `blocks/`:
  - `types/` — `block.json` всех ~52 блоков, собирает `tools/block-json.php`;
  - `home/`, `content/`, `floating/`, `legacy/` — шапка, подвал, товар, 404;
  - `bindings.php` — общие тексты;
  - `render-batch.php` — предпросмотр блоков одним запросом.
- `admin/`:
  - `collections.php` — списки-коллекции на DataViews (заявки, отзывы книги, список отзывов);
  - `settings-form.php` — экраны настроек на DataForm;
  - `abilities.php` — способности;
  - `commands.php` — палитра команд;
  - `convert.php` — шорткоды → блоки.
- `src/` — JS экранов админки, собирается в `build/` и в Git не хранится: catalog, collections, settings, shared, block-controls, bindings, commands, editor-meta.
- `assets/js/view/` — модули Interactivity API на сайте: `site.js` (окно «Перезвоните мне», просмотр каталога, подгонка под экран), `blocks.js`, `cemeteries.js` и их `.min.js`.
- `assets/css/blocks.css` — стили блоков на сайте, с `.min.css`.
- `leads/` — заявки и письма. `reviews/` — Rewio, книга отзывов, письма. `prices/`, `seo/`, `works/`, `places/`, `legal/`.
- `tests/phpunit/` — PHPUnit. `uninstall.php` — список опций и расписаний на удаление.

### Тесты
- `tests/e2e/` — Playwright в WordPress 7.1.4 (CI).
- `tests/smoke/`.
- `tests/probe/` — копия сайта.
- `tests/diag/` — живой сайт, только чтение.

## 6. Стиль сайта

**Для кого.** Пожилые люди, слабое зрение, телефон, тяжёлая ситуация. Отсюда правила:
- **Текст не мельче 16 px (1rem)** нигде. Заголовки разборчивые, строки не длинные.
- **Контраст WCAG 2.2 AA**: текст ≥ 4.5:1, крупный текст и элементы управления ≥ 3:1. Проверка — `tools/check-contrast.mjs` и глазами.
- **Кнопки и ссылки-кнопки** — высота не меньше 44 px на телефоне, цель нажатия ≥ 24×24.
- **Спокойный тон.** Без ярких акцентов, мигания и навязчивых всплывашек.

**Цвета** (`theme.json`, в CSS — только через переменные с запасным значением):

| Цвет | Код | Для чего |
|---|---|---|
| base | `#fbfaf6` | фон |
| base-2 | `#f2efe6` | второй фон |
| surface | `#e6ebdf` | шалфей |
| primary | `#5e7052` | лавр, кнопки |
| secondary | `#3f4d36` | |
| tertiary | `#a9b796` | обводка при наведении |
| accent | `#a88a5a` | бронза |
| contrast | `#2a2c28` | текст |
| contrast-2 | `#66675e` | второстепенный текст |
| line | `#e2ded2` | линии |

В плагине — переменные `--memorial-plugin-*`, каждая с фолбэком на пресет темы:
- цвета и фон: `--memorial-plugin-ink`, `-mute`, `-line`, `-gold`, `-gold2`, `-bg`, `-bg2`, `-sage`, `-bronze`;
- шрифты: `-serif`, `-lora`, `-sans`;
- скругления: `-r` 14px, `-rb` 10px;
- тени: `-sh`, `-sh2`.

Пример: `color: var(--memorial-plugin-ink)`. **Не писать цвета «в лоб»** там, где есть пресет.

**Шрифты.** Все лежат локально, CDN не используются:
- Cormorant Garamond — крупные заголовки, курсив;
- Lora — заголовки карточек и цены;
- системный sans — основной текст.

**Форма.**
- Карточки — белые, скругление 12–14 px, мягкая тень, тонкая линия.
- Обводка при наведении повторяет скругление.
- Кнопки: основная — заливка лавром (`btn--gold`), вторичная — контур (`btn--line`). Скругление `--rb`.

**Блоки.**
- Блок выглядит **одинаково на главной и на внутренних страницах**. Общие правила текста темы — через `:where(.content …)`, чтобы не перебивать блоки.
- Новые стили — в `blocks.css` плагина или в стилях блока, затем `.min` (шаг 4).
- `!important` не добавлять. Стили ядра не перебивать.

**Телефон.**
- Проверять на ширине 390 и 360.
- Нижняя панель «Позвонить / Написать» (`.mbar`) закреплена и не должна ничего закрывать.
- Полоса разделов каталога прилипает под шапкой; сортировка не прилипает.
- В каталоге 1 или 2 колонки — задаётся у типа товара. При одной колонке фото подгоняется так, чтобы на экране были название, цена и «Заказать».
- Высоты, привязанные к экрану:
  - `100lvh` — экран без адресной строки, по нему подгоняется фото;
  - `svh` — когда размер не должен меняться при прокрутке;
  - `dvh` — не использовать для размеров фото: фото «растёт», когда браузер прячет адресную строку.

**Поведение.**
- Скрипты — модули без jQuery: Interactivity API или `assets/js/view/*.js`.
- Анимации короткие (до 0,3 с), обязательно с `prefers-reduced-motion`.
- Окна — `<dialog>` с фокусом и закрытием по Esc.

**Фото.**
- Всегда `srcset`/`sizes`, `loading="lazy"` везде, кроме первого экрана.
- Для карточек каталога есть копия 360 px (`memorial-card`).
- Крупные фото — `large`.

**Скорость.**
- Стили темы встроены в страницу.
- Ассеты плагина — только там, где есть его блоки.
- Внешние скрипты — только Яндекс Метрика, и только после согласия посетителя.

**Каталог (решения 15.11).**
- Карточка в списке: фото (несколько — стрелки и точки), название, строка под названием (если включена у типа), цена, кнопка «Заказать» (если включена у типа). **Без характеристик.**
- Щелчок по фото — крупный просмотр. Он листает **товары**; фото одного товара листаются стрелками, точками и свайпом по фото. Счётчика «N / M» нет.
- Вид просмотра задаётся у типа или категории:
  - **«Только фото»** — тёмный фон, справа (на телефоне под фото) название, цена, характеристики;
  - **«Окно товара»** — белое окно: фото | название, описание, характеристики | цена и «Заказать». Щелчок по фото — крупно только фото этого товара.
- Описание и характеристики товара без своей страницы — в карточке скрытым блоком `.mcard__info[hidden]` (не `<template>`): в исходном HTML для поисковиков, диктор их не читает. Окно (`site.js`) **переносит** блок к себе и возвращает при закрытии (событие `close`) — не копирует. Название, подпись, цена и «Заказать» окна — из видимой карточки.
- Кнопка «Заказать» открывает «Перезвоните мне» с названием товара. Товар попадает в заявку, в письмо (код `{product}`) и в столбец «Товар».

**Импорт и выгрузка товаров (решения 15.11).**
- У каждого товара есть **артикул** (`_mem_sku`, уникальный). Новый товар получает `M-<номер>`; его можно сменить в окне товара. По артикулу импорт находит товар и обновляет его.
- «Каталог → Товары → Выгрузить»: весь каталог, тип или выбранные — Excel (.xlsx) или CSV. Тот же формат читает «Импорт».
- «Каталог → Товары → Импорт»: таблица (.xlsx или .csv) и фото (файлы или ZIP — браузер открывает архив сам). Сначала проверка без записи, потом запись.
- Колонки: Артикул, Тип, Категории, Название, Цена, Цена «от», Старая цена, Единица, Строка под названием, Под заказ, На сайте, Описание, Фото, Alt, «Характеристика: <название>». Списки — с новой строки ячейки или через «;».
- Пустая ячейка — поле не меняется, «-» — очищается. Товары, которых нет в файле, не меняются.
- Новые товары — скрыты, если не отмечено «Сразу опубликовать» (или в колонке «На сайте» — «да»).
- Фото: по колонке «Фото» — из присланных файлов, иначе из медиатеки по имени; пустая колонка — файлы папки с именем артикула (`foto/M-1024/1.jpg`). Повторно не загружаются (SHA-1, или то же имя и размер). Alt — на каждое фото; пусто — название товара. Новому для товара фото — заголовок «Название — фото N» и описание товара в медиатеке.
- Отсутствующий тип, категория или фото — ошибка строки, строка пропускается.
- «Откатить последний импорт»: новые товары — в корзину, изменённые и их фото — как были (журнал `memorial_plugin_import_log`).
- Примеры: Excel (памятка, типы и категории сайта), CSV, ZIP с фото. Импорт — администратор и «Редактор».

**Вопрос–ответ (решения 16.11).**
- Блок «Все вопросы и ответы» (`content/faq.php`) собирает вопросы («Подробности») со всех страниц. Раздел страницы показывает **первый абзац** ответа и «Подробнее» — ссылку на вопрос на его странице.
- Кнопка, заголовок, якорь, текст ссылки «Ещё — на странице…» и **порядок** разделов — в редакторе страницы «Вопрос–ответ» → панель «Разделы вопросов» (мета `_mem_faq_sections`). По умолчанию кнопка — пункт меню, якорь — латиницей из неё.
- **Свой раздел**: на странице «Вопрос–ответ» заголовок H2 и сразу под ним блоки «Подробности». Он входит в разделы, поиск хаба и «Полезно знать»; на странице не повторяется.
- **FAQPage**: каждая страница размечает свои вопросы; хаб — только свои разделы. Один вопрос — одна разметка на сайте (правило Google). ## 7. Стиль админки

**Каркас** — только компоненты WordPress:
- DataViews — для списков;
- DataForm — для форм и настроек;
- `@wordpress/components` — для остального;
- каркас страниц — как у существующих экранов.

Самописных таблиц и форм нет. `WP_List_Table` нет.

**Общий вид экранов плагина** (`src/shared/_admin.scss`):
- тёплый «бумажный» фон `#f6f4ee`;
- белые карточки, скругление 14 px, мягкая тень;
- акцент — шалфей `#4f6145` (затемнён для контраста белого текста);
- стили только для контейнера `.memorial-plugin-admin`, админка WordPress вокруг не меняется.

Новые экраны подключают эти же стили.

**Тексты и подписи.**
- Подпись поля короткая, до ~40 знаков.
- Длинное пояснение (больше ~70 знаков) — за круглой кнопкой **«?»** (`src/shared/hint.js`, `hinted-edit.js`, `boolean-edit.js`). Галочки — отдельными строками, поля не «слипаются».
- Тексты подсказок **без шорткодов**, с текущими путями меню. Например: «Мемориал → Цены → Отдельные цены», «Каталог → Типы и категории».
- Строки на английском в `__()` + русский перевод. Никаких русских строк в коде интерфейса.

**Меню «Мемориал»:** Заявки на обратный звонок, Контакты, Цены, Отзывы (вкладки: Сервисы и виджеты, Отзывы Rewio, Из книги отзывов), Список отзывов, Услуги, Залы для поминок, Кладбища, Аналитика, Документы, Что ищут на сайте, Настройки (вкладки: Функции, Почта, Разрешения).

**Как добавить:**
- **Поле настроек** — в схему экрана (`core/settings.php` и модули). Типы полей: text, textarea, number, checkbox, select, group, repeater, image, page, url, email(s), secret, map, button, note, link, order. Видимость — `show_if`; свёрнутая строка — `summary` / `short`.
- **Список записей** — описать коллекцию в `admin/collections.php`: поля, `source`, `cap`, `hidden`, `trash`, `sort`, `modal`. REST и экран строятся сами.
- **Настройку типа товара** — в `catalog/catalog-types-admin.php` и `src/catalog/types.js`, в подходящий подраздел формы (например «Фото и заказ»). Категория может иметь «Как у типа».
- **Ключевое действие** — способностью (`admin/abilities.php`, со схемами и проверкой прав) и, если уместно, командой палитры (`admin/commands.php`).
- **Права** — `core/permissions.php`. Роли «Редактор» и «Автор» настраиваются на вкладке «Разрешения».

**Поведение.**
- Новая запись (товар, работа) создаётся **только по «Сохранить»**.
- Сохранение — с версией настройки: при конфликте сообщение, а не тихая перезапись.
- Таблица товаров — **только таблица** (без сетки и списка). Есть «Плотность»; новые товары сверху.
- Значения в таблице товаров меняются **щелчком** (`src/catalog/inline-edit.js`): текст и число — поле в ячейке (сохраняют только ✓ и Enter; Esc или щелчок мимо — отмена), выбор — маленькое окно с тем же полем, что в «Изменить». «На сайте» — галочка, сохраняется щелчком (поле с `toggle: { on, off }`). Не правятся щелчком: артикул, фото, описание, дата.
- Описание товара правится в окне товара простым текстом.
- **Коды характеристик** (`catalog/catalog-spec-codes.php`): у характеристики типа поле `code` (латиница из названия, уникальное в типе, при переименовании не меняется). `{spec:код}` в названии или описании товара сайт заменяет значением (как в карточке: число с единицей); пусто — код убирается со скобками. Подстановка — фильтры `the_title` (кроме экранов wp-admin), `single_post_title`, `the_content`, `get_the_excerpt`, SEO-плагины, явно — в описании просмотра, странице товара и Schema.org. В базе, в экранах каталога, выгрузке и импорте — с кодами (`post_title`), итог в таблице — поле `shown`.

## 8. Код

### 8.1 Стандарты
- PHP:
  - WPCS — комментарии заканчиваются точкой, массивы по ключу на строку, нет лишней пустой строки в конце файла;
  - `defined( 'ABSPATH' ) || exit;`;
  - экранирование вывода, санитизация ввода, `current_user_can`, `permission_callback` у каждого REST-маршрута и способности;
  - `$wpdb->prepare`.
- JS:
  - ESLint `@wordpress` — нет затенения имён (`no-shadow`), браузерные глобалы через `window.` (`window.getComputedStyle`);
  - Prettier — делает автоправка;
  - над компонентами `//`, а не `/** */`.
- Все глобальные функции, хуки, опции — с префиксом. Опции плагина — `mem_*` (настройки экранов) или `memorial_plugin_*` (служебные).

### 8.2 Переводы
- Строки на английском.
- После правки — шаг 3 из раздела 3.
- Строки пакетов WordPress, которых нет в переводе WP 7.1, переводятся через `memorial_plugin_vendor_strings()`.

### 8.3 Ассеты
- Подключение только через `wp_enqueue_*` / `wp_register_script_module`.
- Сжатая копия выбирается `memorial_plugin_asset()` / `memorial_theme_asset()`: копия должна быть не старше исходника, при `SCRIPT_DEBUG` берётся исходник.
- ESLint не проверяет `*.min.js`.

### 8.4 Разовые изменения данных (переносы)
- Флаг-опция (`memorial_plugin_<что>_N`): ставится **до** запуска, чтобы не повторяться.
- Журнал изменений (опция без автозагрузки): что было и что стало — для отката.
- Опции флага и журнала, расписания cron — внести в `uninstall.php` и в отключение плагина.
- Сохранять данные **«как есть»**, а не через санитайзер экрана: он написан для формы и на живых данных сбрасывал галочки.
- Тексты записей менять напрямую (`$wpdb->update` + `clean_post_cache`), без ревизий и фильтров сохранения.
- **Сначала холостой прогон** через `diag/*`: что нашлось бы, без записи. Потом настоящий.
- После — сброс кэша страниц (`memorial_plugin_page_cache_clear()`).

### 8.5 Прочее
- Кэш настроек `memorial_plugin_settings()` сбрасывается при записи любой опции `mem_*`.
- Кэш страниц — WP Super Cache. Плагин сам чистит его при сохранении экранов.
- Меню — только «Навигация» (wp_navigation, `memorial_plugin_menu_items()`). Пункты без `id` находят страницу по адресу.
- Подстановки цен — `{price:код}`. Внутри подстановки другие подстановки не раскрываются: это защита от рекурсии, из-за неё был 500.
- Шорткоды `[mem_…]` работают до 3.0.0 и сообщают об устаревании. Новых шорткодов не добавлять, только блоки.
- Фоновые задачи — WP-Cron, небольшими порциями (пример — `catalog/catalog-images.php`).

## 11. Грабли (уроки)

- Коммит, отправленный только в `autofix/<ветка>`, в саму ветку не попадает, если автоправке нечего менять. Ветку пушить всегда.
- Автоправка меняет исходник JS → `.min.js` устаревает → CI падает. Пересобрать.
- Модуль не в `$memorial_plugin_modules` — не загружается.
- В заголовках неразрывные пробелы после коротких слов — в тестах сравнивать без них.
- У элементов с `position:fixed` нет `offsetParent`: видимость проверять через `getClientRects()`.
- `aspect-ratio` + `max-height` сужают блок пропорционально. Нужна явная `width:100%`.
- Конфликт специфичности: `.pv--card .pv__box{align-items:start}` перебивал телефонный столбец. Проверять телефон снимком.
- `dvh` меняется при прокрутке на телефоне.
- `wp-env` по умолчанию включает `SCRIPT_DEBUG`: на копии сайта грузятся исходники, а не `.min`.
- Cyr To Lat переименовал файлы и адреса страниц:
  - старые кириллические адреса в настройках и текстах дают 404 — чинится `core/fix-uploads.php`, журнал в `memorial_plugin_fix_uploads_log`;
  - пункты меню без `id` ищутся по адресу.
- Хостинг ограничивает число PHP-процессов: предпросмотры блоков в редакторе — одним запросом.
- Удаление веток из сессии ИИ не работает — только через `cleanup/*`.
- Две сессии работали параллельно: перед работой `git fetch` и сверка, чужие коммиты не перезаписывать.
- `wp_tempnam()`, `media_handle_sideload()` и др. из `wp-admin/includes` в REST не загружены — подключать самим. PHPUnit этого не ловит (там админка загружена), ловит e2e.
- `get_the_title()` «улучшает» кавычки — для сравнения и выгрузки брать `post_title`.
- Шрифт сайта на Windows (Segoe UI) уже, чем в проверках на Linux: шапка там бывает в **две строки**, а у нас — сразу ☰. Проверять шапку и в двух строках (в сценарии пункты меню сужаются `letter-spacing`).
- Headless Chromium прячет полосы прокрутки: для прокрутки и `100vw` — `chromium.launch( { ignoreDefaultArgs: [ '--hide-scrollbars' ] } )`.
- Скрытое (`visibility:hidden`) подменю тоже расширяет страницу.
- `tools/css-check.mjs` не видит стилей темы — они встроены в страницу (`<style>` без `data-href`). Для правок `main.css` — сценарий «стили: правка шапки…» в `probe.spec.js`: вычисленные стили каждого элемента с правкой и без неё.
