# Переход на блоковую архитектуру — миграция и откат

Тема Memorial Modern 4.1.0 (`memorial_speshu`) → **5.0.0** (`memorial-theme`), плагин Memorial Core 1.15.0 (`memorial-core`) → **Memorial Plugin 2.0.0** (`memorial-plugin`). Сначала — итог и порядок обновления рабочего сайта, ниже — подробности по этапам 1–8.

## Итог: было → стало

| Было (4.1.0 / 1.15.0) | Стало (5.0.0 / 2.0.0) |
|---|---|
| Классическая тема: PHP-шаблоны, «Мемориал → Оформление», кастомайзер | Блоковая тема: `theme.json` v3, `templates/`, `parts/`, `patterns/`, варианты стиля «Бронза», «Камень», «Тёмная»; всё правится в «Внешний вид → Редактор» |
| Меню «Внешний вид → Меню» | Блок «Навигация» (меню перенесено один раз) |
| Шапка, подвал, хлебные крошки, страница товара, раздел каталога, 404 — PHP-шаблоны темы | Блоки плагина в частях и шаблонах темы (`memorial-plugin/topbar`, `header-contacts`, `footer-contacts`, `menu-columns`, `footer-legal`, `breadcrumbs`, `product`, `catalog-archive`, `not-found`…) |
| 16 шорткодов `[mem_…]` на страницах | Блоки плагина (таблица в «Этап 3»); шорткоды работают как слой совместимости до 3.0.0 |
| Шорткоды внутри текста (`[mem_cat_price]`, `[mem_phone]`…) | «Значение сайта» — формат текста в редакторе |
| Шорткоды в полях SEOPress | Переменные `%%mem_…%%` |
| Окно «Перезвоните мне», панель на телефоне, плашка cookie — вывод в `wp_footer` | Блоки, которые сами встают в подвал (Block Hooks) |
| Экраны настроек на PHP, `WP_List_Table`, мета-боксы, jQuery | DataForm, DataViews, `@wordpress/admin-ui`, панели блочного редактора (таблица в «Этап 4») |
| Действия только кнопками админки | 12 способностей (Abilities API) — из интерфейса, палитры команд Ctrl/Cmd + K и REST (таблица в «Этап 5») |
| `front.js` (jQuery-подобный код на всех страницах) | Interactivity API: модули `view/blocks.js`, `view/cemeteries.js` — только на страницах с блоками |
| Свои цвета и шрифты в CSS плагина | Пресеты темы с запасными значениями; в чужой блоковой теме недостающие пресеты подставляются из её палитры |
| Кэш страниц, сжатие HTML, WebP, «Мемориал → Скорость» | Удалено: кэш и сжатие — у хостинга, фото обрабатывает WordPress (этап 3) |
| Справка «Шорткоды и блоки» | Удалена: блоки с описаниями — во вставке блоков, шорткоды переводятся в блоки на экране «Перевод в блоки» (этап 8) |
| Интерфейс на русском в коде | Строки на английском в функциях перевода, перевод ru_RU в комплекте (этап 8) |

**Данные не переносятся в другие места:** настройки (`mem_*`), мета-поля (`_mem_*`), типы записей и таксономии (`mem_product`, `mem_cat`…) остались прежними. Разовые переносы (дизайн → стили сайта, меню → навигация, главная → шаблон, контент → блоки) ничего не удаляют, а то, что меняют, сохраняют для отката (опции `memorial_theme_*_migrated`, `memorial_plugin_*_migrated`, редакции записей).

## Обновление рабочего сайта с 4.1.0 / 1.15.0

1. **Резервная копия** файлов и базы (в хостинге или UpdraftPlus).
2. **Выгрузка**: Actions → «Деплой на сайт» с веткой релиза. Новые папки `themes/memorial-theme`, `plugins/memorial-plugin` встают рядом со старыми; старые не трогаются.
3. **Плагины → Memorial Plugin → Активировать** — переключение на новую тему и плагин (подробно — «Порядок обновления сайта» ниже).
4. **Первый вход в админку** выполняет разовые переносы: оформление → стили сайта, меню → навигация, главная → шаблон, уборка за модулями скорости, удаление IP из старых заявок.
5. **«Мемориал → Аналитика» → Сохранить** — подтвердить режим Метрики.
6. **«Мемориал → Перевод в блоки»**: «Предпросмотр и перевод» → «Перевести» для всех записей с шорткодами (можно постепенно; до 3.0.0 шорткоды и так работают).
7. **Проверка**: главная, каталог и товар, «Цены», «Контакты», «Вопрос–ответ», «Отзывы», окно «Перезвоните мне», плашка cookie; экраны «Мемориал → …», «Каталог → Товары», палитра команд (Ctrl/Cmd + K). Язык сайта — русский (`ru_RU`): интерфейс плагина и темы на русском из их папок `languages/`.

## Откат с 5.0.0 / 2.0.0

- **Целиком на 4.1.0 / 1.15.0** — раздел «Откат» ниже: выключить Memorial Plugin, включить Memorial Core и тему из папки `memorial_speshu`. Данные общие, поэтому сайт работает как до обновления. Страницы, уже переведённые в блоки, сначала откатите: «Мемориал → Перевод в блоки» → «Откатить» (или «Редакции» записи) — старый плагин показывает шорткоды, а не блоки.
- **Только главная** — «Сбросить» шаблон «Главная» (см. «Главная из блоков»).
- **Только одна страница** — «Откатить» на экране «Перевод в блоки» или «Редакции».
- **Перевод интерфейса** — если нужен английский интерфейс, смените язык профиля пользователя; файлы `languages/` можно не трогать.

## Что переименовано (этап 1)

| Было | Стало |
|---|---|
| Папка темы `memorial_speshu`, text domain `memorial` | `memorial-theme`, text domain `memorial-theme` |
| Папка плагина `memorial-core`, файл `memorial-core.php`, text domain `memorial-core` | `memorial-plugin`, `memorial-plugin.php`, `memorial-plugin` |
| Функции плагина `mem_*`, `mem_core_*`; константы `MEM_CORE_*`, `MEM_*` | `memorial_plugin_*`; `MEMORIAL_PLUGIN_*` |
| Функции темы `mem_*`, `memorial_*`; `MEM_VER` | `memorial_theme_*`; `MEMORIAL_THEME_VER` |
| Свои хуки (`mem_admin_pages`, `mem_rewio_cron`, `mem_core_blocks_css`…) | `memorial_plugin_*` |
| Константа для wp-config `MEM_NO_PAGE_CACHE` | `MEMORIAL_PLUGIN_NO_PAGE_CACHE` — **проверьте wp-config.php**, если она там была |

**Не переименовано (данные):** ключи настроек (`mem_home`, `mem_prices`…), мета-поля (`_mem_price`…), типы записей и таксономии (`mem_product`, `mem_cat`…), шорткоды (`[mem_…]`), REST `mem/v1`, AJAX-действия. Поэтому старая и новая версии работают на одной базе — это и делает откат простым.

**Отложено до этапов 3–4** (код всё равно переписывается): CSS-классы вывода и админки, handles админских скриптов, JS-объекты (`memTrack`, `memCM`…), AJAX-действия. Классы `.memorial-plugin-*` появятся вместе с блоками.

## Порядок обновления сайта

1. Выгрузка (deploy.yml) кладёт на хостинг новые папки `themes/memorial-theme` и `plugins/memorial-plugin`. Старые папки `memorial_speshu` и `memorial-core` **не удаляются** — сайт продолжает работать на них.
2. Пока активен Memorial Core, новый плагин ничего не загружает и показывает подсказку в админке.
3. **Плагины → Memorial Plugin → Активировать.** При активации плагин сам:
   - выключает Memorial Core (его хук выключения снимает свои расписания, правила `.htaccess` и кэш);
   - снимает оставшиеся расписания под старыми именами (`mem_rewio_cron`, `mem_rewio_cron_once`, `mem_logos_cron`, `mem_img_job_tick`);
   - копирует `theme_mods_memorial_speshu` → `theme_mods_memorial-theme` (только если у новой темы ещё нет своих настроек) и включает тему `memorial-theme`;
   - записывает, что сделал, в опцию `memorial_plugin_switchover`.
4. На следующем запросе плагин пересобирает адреса товаров и работ, ставит регулярную загрузку отзывов Rewio под новым именем хука и продолжает незаконченное пересжатие фото.
5. В админке появится просьба подтвердить режим Метрики (см. ниже) — откройте «Мемориал → Аналитика» и сохраните.

Проверка после переключения: главная, каталог, товар, «Цены», «Контакты»; разделы «Мемориал → …» открываются; автотесты `memorial-tests` проходят так же, как на 4.1.0 (кроме тестов, привязанных к удаляемым функциям — см. STANDARDS_REPORT.md по мере появления).

## Откат

1. Плагины → Memorial Plugin → Деактивировать.
2. Плагины → Memorial Core → Активировать.
3. Внешний вид → Темы → Memorial Modern из папки `memorial_speshu` (версия 4.1.0) → Активировать. Её настройки (`theme_mods_memorial_speshu`) не менялись.
4. «Мемориал → Отзывы Rewio» → «Сохранить» — чтобы старый плагин заново поставил регулярную загрузку отзывов.

Данные не теряются: обе версии читают одни и те же настройки и записи. Ключ `mem_metrika` получает поле `counter.load` — старый плагин его просто не читает.

Старые папки и `theme_mods_memorial_speshu` удаляются в 2.1.0.

## Метрика: три режима загрузки

В «Мемориал → Аналитика → Счётчик» появилось поле «Как загружается Яндекс Метрика»:

| Режим | Счётчик | Плашка cookie |
|---|---|---|
| После согласия (по умолчанию для новых сайтов) | `tag.js` — только после «Принять» | спрашивает согласие |
| Всегда | на всех страницах сразу, асинхронно, внизу страницы | уведомляет («Понятно») — нужна и виджету отзывов |
| Выключено | кода Метрики нет | как выбрано в «Плашка о cookie» (для других счётчиков и виджетов) |

При обновлении режим выбирается по тому, как сайт фактически работал:

| Было | Стало |
|---|---|
| номер счётчика не указан | Выключено |
| плашка «Спрашивать согласие» | После согласия |
| «Только уведомлять» или «Без плашки» | Всегда |

Администратор видит просьбу подтвердить режим, пока не сохранит страницу «Аналитика» (даже без изменений).

Отзыв согласия: если посетитель сначала нажал «Принять», а потом через «Настройки cookie» — «Отклонить», счётчик отключается (`disableYaCounter<номер>`), cookie Метрики (`_ym*`) удаляются. Уже отправленные данные отозвать нельзя — это ограничение Метрики, оно указано в политике cookie.

## Этап 3: блоки плагина

### Модули скорости удалены

Кэш страниц и блоков, сжатие HTML, относительные адреса, пересжатие фото в WebP, автосжатие CSS/JS на сайте и экран «Мемориал → Скорость» удалены (решение 5): кэш страниц и сжатие делает хостинг, фото WordPress 7.1 обрабатывает при загрузке сам.

При первом входе администратора в админку после обновления плагин убирает за собой:
- блок `# BEGIN Memorial cache … # END Memorial cache` из `.htaccess`;
- папку `wp-content/cache/memorial/`;
- задания расписания пересжатия фото.

Что сделано — в опции `memorial_plugin_speed_removed`. Настройка `mem_speed` остаётся до 2.1.0. Сжатые копии `.min.css` / `.min.js` теперь собираются только командой `php tools/minify.php` (CI проверяет, что они свежие). Кнопка «очистить кэш» (этап 5) чистит только объектный кэш и временные данные плагина — серверный кэш хостинга ей недоступен.

| `[mem_cat_list]` | Подразделы каталога `memorial-plugin/category-list` | 2 |
| `[mem_cat_photos]` | Фото из каталога `memorial-plugin/category-photos` | 1 |
| `[mem_cemeteries]` | Кладбища `memorial-plugin/cemeteries` | 1 |

| `[mem_bookreviews]` | Книга отзывов `memorial-plugin/book-reviews` | — |
| `[mem_rewio]` | Отзывы Яндекс Карт `memorial-plugin/rewio-reviews` | 1 |

Шорткоды внутри текста стали «значениями сайта» — формат текста в редакторе (кнопка «Значение сайта» на панели абзаца): `[mem_cat_price]` (цена от), `[mem_cat_count]` (число моделей), `[mem_price]` (цена из «Цен»), `[mem_years]`, `[mem_phone]`, `[mem_operator]`, `[mem_doc]`. В тексте это `<span class="memorial-plugin-value" data-value="…">`, на странице значение всегда текущее.

Шорткоды продолжают работать до 3.0.0 (удаление). С 12.11.2026 каждый шорткод в тексте сообщает об устаревании (`_deprecated_function()`, видно в `debug.log` при `WP_DEBUG`) и называет блок-замену, а консоль администратора показывает, сколько записей ещё с шорткодами. Блоки и «значения сайта» шорткоды не вызывают — они берут реализацию напрямую (`core/shortcodes-compat.php`).

### Перевод старого контента: «Мемориал → Convert to blocks»

(С этапа 8 экран называется «Перевод в блоки» — интерфейс переведён.)

Только по кнопке, не автоматически (решение 9).
1. Список — все записи, где ещё есть `[mem_…]` (в тексте или в полях SEOPress).
2. «Предпросмотр и перевод» показывает изменения так же, как экран редакций; «Перевести» можно для одной записи или для нескольких (пачками по 10).
3. Перед сохранением текущий текст записи сохраняется редакцией; номер редакции и старые значения полей SEO — в мете `_memorial_plugin_converted`.
4. «Откатить» возвращает текст из этой редакции и поля SEO.

Проверено на копии базы сайта: 28 записей с шорткодами переводятся полностью, после перевода в них не остаётся `[mem_`.

### SEO: переменные SEOPress вместо шорткодов

Реестр `memorial_plugin_seo_registry()` — переменные `%%mem_phone%%`, `%%mem_years%%`, `%%mem_cat_price_ograda%%` для SEOPress (а также Yoast и Rank Math, если сменится SEO-плагин). В базе шорткод был в одном поле — SEO-заголовок страницы «Оградки» (`[mem_cat_price cat="Модели оградок и цены"]`); перевод контента заменит его на `%%mem_cat_price_ograda%%`. Описания страниц шорткодов не содержат.

### Плавающие элементы

«Панель на телефоне», окно «Перезвоните мне» и плашка cookie — блоки плагина, которые сами встают в конец подвала (Block Hooks). Открепить блок: Внешний вид → Редактор → Шаблоны → часть «Подвал» → выбрать блок → панель «Плагины». Без плашки cookie в режиме «После согласия» Метрика не загрузится.

### Иконки

Иконки сайта зарегистрированы в реестре иконок WordPress (SVG Icon API) как коллекция «Memorial» и доступны в блоке «Иконка». Реестр 7.1 не хранит обводку, поэтому линии иконок переведены в контуры Inkscape; совпадение с прежними иконками проверено попиксельно (workflow «Иконки → SVG Icon API», отчёт — ветка `ci-icons`).

### Главная из блоков

При первом входе администратора шаблон главной сохраняется как шаблон сайта: первый экран и разделы в порядке из «Мемориал → Главная страница». Тексты — обычными блоками (правятся на месте в «Внешний вид → Редактор»), данные — блоками плагина. Что сделано — в опции `memorial_plugin_home_migrated`.

Список услуг (карточки с фото и ценами) пока остаётся в «Мемориал → Главная страница» — это данные, а не раскладка страницы; на этапе 4 они переходят в экран на DataForm, после этого экран «Главная страница» убирается.

**Версия темы и паттерны.** WordPress запоминает список паттернов темы по номеру версии из `style.css`. Если поменять файлы в `patterns/`, не меняя версию, сайт продолжит показывать старый список (на главной будет пусто, пока кэш не сбросится). Поэтому версия темы меняется при каждом выпуске: этап 3 — `5.0.0-alpha.3`.

**Откат главной:** Внешний вид → Редактор → Шаблоны → «Главная» → ⋮ → «Сбросить» — главная снова строится из `mem_home` (настройка не удаляется до 2.1.0).

## Этап 4: админка на DataViews / DataForm

Классические экраны (WP_List_Table, мета-боксы, jQuery-скрипты, admin-ajax) заменены на экраны на `@wordpress/dataviews` и `@wordpress/admin-ui` (собраны внутрь плагина). Данные хранятся в тех же опциях и полях, переноса базы нет.

| Экран | Было | Стало |
|---|---|---|
| «Мемориал → Контакты, Цены, Отзывы, Залы, Кладбища, Документы, Аналитика, Функции, Услуги» | формы на PHP | DataForm, сохранение через REST `memorial-plugin/v1/settings/<опция>` тем же санитайзером |
| «Мемориал → Заявки» | список записей `mem_lead` | DataViews + DataForm (`memorial-plugin/v1/collections/leads`) |
| Отзывы из книги | список и мета-бокс `mem_bookrev` | DataViews + DataForm (`collections/bookrev`) |
| «Каталог → Товары» | jQuery-таблица, колонки и быстрое редактирование списка | DataViews: вкладки по типам, характеристики типа — колонками, форма товара, действия над несколькими товарами (цены, категории, показать/скрыть, копия, объединение, корзина), «Добавить из фото» |
| «Каталог → Типы и категории» | jQuery-экран | DataForm (настройки типа), редактор характеристик, DataViews (категории) |
| «Каталог → Страницы товаров» | форма на PHP | DataForm |
| «Наши работы → Работы», «Виды работ» | jQuery-экраны, классический редактор | DataViews + DataForm |
| «Мемориал → Что ищут на сайте» | таблица на PHP | DataViews |
| Редактор товара, работы, страницы | мета-боксы | панели в боковой колонке блочного редактора |

Порядок на сайте (раньше — перетаскиванием) меняется пунктами «Выше» / «Ниже» в меню строки или полем «Порядок» в форме.

**Поля в редакторе.** Мета товаров (`_mem_price`, `_mem_price_old`, `_mem_unit`, `_mem_price_from`, `_mem_on_order`, `_mem_sub`, `_mem_specs`, `_mem_gallery`), работ (`_mem_photos`, `_mem_size`, `_mem_year`, `_mem_rows`, `_mem_example`) и страниц (`_mem_products`, `_mem_q`, `_mem_qa`) зарегистрирована для REST (`admin/editor-meta.php`) и правится в панелях «Цена», «Карточка», «Фото, размер и цены», «Товары на странице», «Полезно знать». Работы теперь открываются в блочном редакторе; у новых товаров и работ — шаблон с подсказкой в первом абзаце. Старый текст работ (без блоков) выводится как раньше.

**Корзина.** Восстановить удалённый товар или работу — по ссылке «Корзина» на экране списка (классический экран корзины оставлен).

**Что пока осталось классическим:** разовый «Перенос каталога со страниц» (служебный инструмент, в меню не выводится). Справка «Шорткоды и блоки» удалена на этапе 8.

**Откат.** Данные не менялись, поэтому откат — установка предыдущей версии плагина.

## Этап 5: Abilities API и палитра команд

**Способности** (`admin/abilities.php`, категория `memorial`). Каждая — со схемами входа и выхода и своей проверкой прав. Вызываются из экранов плагина и из палитры команд через `@wordpress/abilities` (если модуль недоступен — через REST `/wp-abilities/v1/abilities/<имя>/run` с теми же проверками).

| Способность | Что делает | Права | Где используется |
|---|---|---|---|
| `memorial-plugin/list-leads` | заявки «Перезвоните мне» (новые / все) | edit_posts | палитра: «Кому перезвонить» |
| `memorial-plugin/set-lead-done` | отметить «Перезвонили» | правка заявки | «Заявки» → «Отметить, что перезвонили» (можно несколько) |
| `memorial-plugin/list-products` | товары с ценой и видимостью | edit_posts | REST, агенты |
| `memorial-plugin/update-product` | название, цена, «от», единица, строка, видимость | правка товара | REST, агенты |
| `memorial-plugin/change-prices` | цены нескольких товаров: %, ₽, одна цена, округление | edit_posts | «Товары» → «Изменить цены…» |
| `memorial-plugin/set-visibility` | показать / скрыть товары или работы | edit_posts | «Товары», «Работы» → «Показать/Скрыть» |
| `memorial-plugin/create-products` | товары из фото | edit_posts + upload_files | REST |
| `memorial-plugin/export-catalog` | каталог в CSV (Excel открывает как есть) | edit_posts | «Товары» → «Экспорт в CSV», палитра |

Заявки, перевод контента и очистка статистики не помечены как публичные (`meta.public = false`): это персональные данные или правка текста — они доступны только экранам сайта и REST с вошедшим пользователем, не агентам.

**Палитра команд (Ctrl/Cmd + K)** — `admin/commands.php`, `src/commands`. Команды есть на всех страницах админки и в редакторах; пользователю показываются только экраны, на которые у него есть права:
- переход на экраны плагина: заявки, товары, типы и категории, работы, виды работ, «Что ищут», «Convert to blocks», книга отзывов и все страницы настроек «Мемориал: …»;
- «Экспорт каталога в CSV» — файл скачивается сразу;
- «Кому перезвонить» — сколько заявок ждут звонка, и переход к списку;
- в редакторе страницы, где остались шорткоды, — «Перевести шорткоды этой страницы в блоки».

## Этап 6: стили и интеграция с темой

**Цвета и шрифты блоков — пресеты темы.** В `assets/css/blocks.css` больше нет собственных переменных темы Memorial (`--gold`, `--ink`, `--mute`…). Блоки берут пресеты `theme.json` с фолбэками, например `var(--wp--preset--color--primary, #5e7052)`. Используются пресеты:
- цвета: `base`, `base-2`, `surface`, `primary`, `secondary`, `tertiary`, `accent`, `contrast`, `contrast-2`, `line`, `on-primary`;
- шрифты: `cormorant-garamond`, `lora`, `system-sans`.

Вариации стилей («Внешний вид → Редактор → Стили») меняют и блоки плагина.

**Другая тема.** Если у блочной темы нет какого-то из этих пресетов, плагин подставляет её собственный цвет: `primary` ← `accent` / `accent-1`, `contrast` ← `foreground` / `text` и т. д. Подстановка делается встроенным стилем (`wp_get_global_settings()` + `wp_add_inline_style()`) и кэшируется до смены темы или палитры. У темы Memorial все пресеты есть, подстановок нет.

**Условная загрузка.**
- `blocks.css` и `front.js` теперь стиль и скрипт каждого блока `memorial-plugin/*`: WordPress подключает их только на страницах с такими блоками.
- На время работы старых шорткодов файлы подключаются при выводе шорткода `[mem_…]`.
- В теме Memorial блоки плагина есть в шапке и подвале, поэтому стили есть на всех страницах.
- В редакторе те же стили подключаются в окно страницы.

**Interactivity API.** Блок «Кладбища» (фильтр по статусу захоронений и карта, которая загружается при раскрытии «Подробнее») переведён с общего `front.js` на хранилище `memorial-plugin/cemeteries` (script module `assets/js/view/cemeteries.js`). Производное состояние вычисляется и на сервере, поэтому первая отрисовка совпадает с итоговой. Остальные части `front.js` пока работают как раньше и будут переведены по тому же образцу: вкладки и «Показать ещё» отзывов, сортировка и «Показать ещё» каталога, листание фото товара, «Наши работы», поиск «Вопрос–ответ» и «Полезно знать».

**Классы.** Классы блоков оставлены прежними (`mcat`, `mfaq`, `mguide`, `mem-cem`, `rwo`…): они стоят в сохранённом контенте и в вариациях стилей. Новые элементы плагина получают префикс `memorial-plugin-`.

## Интерактивность блоков: Interactivity API

Поведение блоков на сайте перенесено со старого `assets/js/front.js` (удалён) на Interactivity API. Модуль `assets/js/view/blocks.js` (script module `memorial-plugin-view`) подключается вместе с блоками плагина, а пока работают старые шорткоды — и при их выводе. Корень каждого блока размечен директивами `data-wp-interactive` / `data-wp-init` / `data-wp-on--*`:

## Этап 7: безопасность, доступность, тесты

**Безопасность** — проверены все входы плагина:
- **REST.** У каждого маршрута есть `permission_callback`. Публичных маршрутов два, оба с защитой:
  - `mem/v1/callback` (заявка): скрытое поле от ботов, проверка времени заполнения, телефона и согласия, не больше 5 заявок за 15 минут с одного адреса;
  - `mem/v1/consent` (журнал согласий на cookie): теперь один голос в сутки с адреса, хранится только хэш адреса — журнал больше нельзя «накрутить».
- **admin-ajax.** Единственный публичный обработчик `mem_sq` («Что ищут»): не больше 40 запросов в час с адреса. Хранится только текст запроса, без адресов; телефоны и ссылки отбрасываются.
- **Способности.** Свой `permission_callback` и проверка входа по схеме — это проверяют тесты PHPUnit.
- **Персональные данные.** IP-адрес в заявках больше не сохраняется: он нужен только для ограничения частоты. IP из старых заявок удаляются один раз при первом входе в админку.
- **SQL.** Прямой SQL — один запрос на экране «Convert to blocks», через `$wpdb->prepare`.
- **Файлы.** `defined( 'ABSPATH' ) || exit;` есть во всех PHP-файлах плагина и темы. Без него остались только утилиты и тесты, которые на сайт не выгружаются.
- **Экспорт CSV.** Значения, начинающиеся с `=`, `+`, `-`, `@`, не выполняются в Excel как формулы.

**Доступность (WCAG 2.2 AA):**
- **Контраст.** `tools/check-contrast.mjs` проверяет 9 пар цветов в палитре темы и трёх вариациях (входит в `npm run lint:json`). Все пары проходят: текст ≥ 4.5 : 1, элементы интерфейса ≥ 3 : 1.
- **Фокус.** Видимый фокус у всех кнопок и ссылок блоков, в том числе у кнопок без оформления («Читать полностью» в отзывах); у поля поиска обводка вместо бледной тени.
- **Анимации.** При `prefers-reduced-motion` анимации, переходы и плавная прокрутка блоков выключены.
- **Размер нажатия.** Цели нажатия не меньше 24 × 24 px (стрелки фото 28 px, кнопки 44 px).
- **e2e.**
  - `tests/e2e/a11y.spec.js` — axe (`wcag2a/aa`, `wcag21aa`, `wcag22aa`) на главной, странице со всеми блоками плагина, поиске, каталоге и 404. Серьёзные и критичные нарушения — ошибка проверки.
  - Проверка клавиатуры: ссылка «к содержимому» — первая остановка Tab, меню открывается и закрывается с клавиатуры.

**Тесты:**
- **PHPUnit** (`memorial-plugin/tests/phpunit`, окружение тестов wp-env, часть 1 проверки в WordPress):
  - способности — регистрация, отказ подписчику, проверка входа, расчёт цен, «по запросу» не меняется, защита CSV, скрыть/показать;
  - REST — права на настройки, заявки, каталог, типы;
  - логика — строки работ, год, слияние настроек, страница с товарами, подстановка пресетов для чужой темы.
- **e2e:** Interactivity API (фильтр кладбищ, модуль вместо `front.js`), способности, палитра команд, все экраны админки.

## Этап 8: документация, переводы, релиз

**Версии:** тема 5.0.0, плагин 2.0.0.

**Переводы.**
- **Строки.** Все строки интерфейса плагина и темы — на английском, в функциях перевода с text domain `memorial-plugin` / `memorial-theme`:
  - PHP — `__()`, `_n()`, `_x()`, `esc_html__()`…;
  - экраны админки — `@wordpress/i18n`;
  - модуль блоков — через `getConfig( 'memorial-plugin' )` Interactivity API: строки и формы множественного числа готовит сервер (`memorial_plugin_view_i18n()`), JS выбирает форму по `Intl.PluralRules`;
  - `main.js` темы — через `window.memorialThemeI18n`.
- **Файлы перевода.**
  - Шаблоны перевода: `memorial-plugin/languages/memorial-plugin.pot` (1227 строк) и `memorial-theme/languages/memorial-theme.pot` (112 строк).
  - Русский перевод `*-ru_RU.po` переведён полностью; из него собраны `.mo` и, для экранов админки, `memorial-plugin-ru_RU-<handle>.json`.
  - Плагин и тема загружают свои переводы сами (`load_plugin_textdomain` на `init`, `load_theme_textdomain` на `after_setup_theme`).
- **Переводимые части темы.**
  - Шапка, подвал и текст «Ничего не найдено» — скрытые паттерны `memorial-theme/header`, `footer`, `no-results`; части и шаблоны ссылаются на них (как в Twenty Twenty-Five).
  - Названия цветов, шрифтов, размеров и вариантов стиля в `theme.json` переводятся по схеме WordPress.
- **Что не переводится.** Содержимое сайта — тексты страниц по умолчанию (главная, услуги, пакеты, шаблоны документов по 152-ФЗ, вопросы «Полезно знать»), слова для поиска и значения параметров шорткодов (`vid="карточки"`) — это данные русскоязычного сайта, а не интерфейс. Они остались русскими, при смене языка их не нужно переводить.
- **Как менять.** Сменили строки:
  1. `php tools/i18n.php pot` — обновить `.pot`;
  2. дополнить `*-ru_RU.po` (Poedit или вручную);
  3. `php tools/i18n.php build`.

  CI (`php tools/i18n.php check`) проверяет, что `.pot` свежий, всё переведено и `.mo`/`.json` собраны из `.po`. Кроме того, `wp i18n make-pot` в wp-env не находит строк, которых нет в `.pot`.
- **Ранняя загрузка.** Если переводы загружаются раньше `init` (уведомление WordPress 6.7+), CI выдаёт ошибку. Названия функций для «Мемориал → Функции» поэтому вынесены в `memorial_plugin_optional_labels()`: список модулей читается до `init`.

**Удаление плагина (`uninstall.php`).**
- **По умолчанию** удаляется только то, что плагин восстановит сам: расписания, временные данные и кэш отзывов Rewio. Товары, работы, книга отзывов, заявки, категории, настройки и поля страниц остаются.
- **Полное удаление.** Чтобы удалить и их, перед удалением плагина добавьте в `wp-config.php` строку `define( 'MEMORIAL_PLUGIN_DELETE_DATA', true );`. Предварительно сделайте резервную копию базы — это необратимо.

**Удалено.** Справка «Мемориал → Шорткоды и блоки» (`admin/help.php`): конструктор шорткодов противоречил переходу на блоки. Описания блоков — во вставке блоков, перевод старых страниц — «Мемориал → Перевод в блоки», шорткоды работают до 3.0.0.

**Документы.**
- `README.md` — установка, сборка, структура, переводы;
- `CHANGELOG.md` — изменения выпуска;
- `memorial-plugin/readme.txt`, `memorial-theme/readme.txt` — описание в формате WordPress;
- `STANDARDS_REPORT.md` — линтеры, доступность, контраст, тесты, допущения и отклонения от ТЗ.
