# Переход на блоковую архитектуру — миграция и откат

Документ пополняется по этапам. Здесь — этап 1: новые имена папок и префиксов, переключение со старых папок, режимы Метрики.

## Что переименовано (этап 1)

| Было | Стало |
|---|---|
| Папка темы `memorial_speshu`, text domain `memorial` | `memorial-theme`, text domain `memorial-theme` |
| Папка плагина `memorial-core`, файл `memorial-core.php`, text domain `memorial-core` | `memorial-plugin`, `memorial-plugin.php`, `memorial-plugin` |
| Функции плагина `mem_*`, `mem_core_*`; константы `MEM_CORE_*`, `MEM_*` | `memorial_plugin_*`; `MEMORIAL_PLUGIN_*` |
| Функции темы `mem_*`, `memorial_*`; `MEM_VER` | `memorial_theme_*`; `MEMORIAL_THEME_VER` |
| Свои хуки (`mem_admin_pages`, `mem_rewio_cron`, `mem_core_blocks_css`…) | `memorial_plugin_*` |
| Константа для wp-config `MEM_NO_PAGE_CACHE` | `MEMORIAL_PLUGIN_NO_PAGE_CACHE` — **проверьте wp-config.php**, если она там была |

**Не переименовано (данные):** ключи настроек (`mem_home`, `mem_prices`…), мета-поля (`_mem_price`…), типы записей и таксономии (`mem_product`, `mem_cat`…), шорткоды (`[mem_…]`), REST `mem/v1`, AJAX-действия. Поэтому старая и новая версии работают на одной базе — это и делает откат простым.

**Отложено до этапов 3–4** (код всё равно переписывается): CSS-классы вывода и админки, handles админских скриптов, JS-объекты (`memTrack`, `memCM`…), AJAX-действия. Классы `.memorial-plugin-*` появятся вместе с блоками.

## Порядок обновления сайта

1. Выгрузка (deploy.yml) кладёт на хостинг новые папки `themes/memorial-theme` и `plugins/memorial-plugin`. Старые папки `memorial_speshu` и `memorial-core` **не удаляются** — сайт продолжает работать на них.
2. Пока активен Memorial Core, новый плагин ничего не загружает и показывает подсказку в админке.
3. **Плагины → Memorial Plugin → Активировать.** При активации плагин сам:
   - выключает Memorial Core (его хук выключения снимает свои расписания, правила `.htaccess` и кэш);
   - снимает оставшиеся расписания под старыми именами (`mem_rewio_cron`, `mem_rewio_cron_once`, `mem_logos_cron`, `mem_img_job_tick`);
   - копирует `theme_mods_memorial_speshu` → `theme_mods_memorial-theme` (только если у новой темы ещё нет своих настроек) и включает тему `memorial-theme`;
   - записывает, что сделал, в опцию `memorial_plugin_switchover`.
4. На следующем запросе плагин пересобирает адреса товаров и работ, ставит регулярную загрузку отзывов Rewio под новым именем хука и продолжает незаконченное пересжатие фото.
5. В админке появится просьба подтвердить режим Метрики (см. ниже) — откройте «Мемориал → Аналитика» и сохраните.

Проверка после переключения: главная, каталог, товар, «Цены», «Контакты»; разделы «Мемориал → …» открываются; автотесты `memorial-tests` проходят так же, как на 4.1.0 (кроме тестов, привязанных к удаляемым функциям — см. STANDARDS_REPORT.md по мере появления).

## Откат

1. Плагины → Memorial Plugin → Деактивировать.
2. Плагины → Memorial Core → Активировать.
3. Внешний вид → Темы → Memorial Modern из папки `memorial_speshu` (версия 4.1.0) → Активировать. Её настройки (`theme_mods_memorial_speshu`) не менялись.
4. «Мемориал → Отзывы Rewio» → «Сохранить» — чтобы старый плагин заново поставил регулярную загрузку отзывов.

Данные не теряются: обе версии читают одни и те же настройки и записи. Ключ `mem_metrika` получает поле `counter.load` — старый плагин его просто не читает.

Старые папки и `theme_mods_memorial_speshu` удаляются в 2.1.0.

## Метрика: три режима загрузки

В «Мемориал → Аналитика → Счётчик» появилось поле «Как загружается Яндекс Метрика»:

| Режим | Счётчик | Плашка cookie |
|---|---|---|
| После согласия (по умолчанию для новых сайтов) | `tag.js` — только после «Принять» | спрашивает согласие |
| Всегда | на всех страницах сразу, асинхронно, внизу страницы | уведомляет («Понятно») — нужна и виджету отзывов |
| Выключено | кода Метрики нет | как выбрано в «Плашка о cookie» (для других счётчиков и виджетов) |

При обновлении режим выбирается по тому, как сайт фактически работал:

| Было | Стало |
|---|---|
| номер счётчика не указан | Выключено |
| плашка «Спрашивать согласие» | После согласия |
| «Только уведомлять» или «Без плашки» | Всегда |

Администратор видит просьбу подтвердить режим, пока не сохранит страницу «Аналитика» (даже без изменений).

Отзыв согласия (очистка cookie Метрики, отключение счётчика) делает блок плашки cookie на этапе 3.
